`packages.lock.json` records, for each package of a project, the resolved version and the content hash of its `.nupkg`. Switch it on with `<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>` in the project; {{if eq .Client "dotnet"}}`dotnet restore --locked-mode`{{else if eq .Client "nuget"}}`nuget restore -LockedMode`{{else}}the `RestoreLockedMode` property of the project (or `dotnet restore --locked-mode` on a build server){{end}} then fails when the lock file and the project disagree and restores exactly what the file names.

The lock file does not record the address of a source, so it moves between repositories that serve the same bytes: point the `nuget.config` at another repository and the restore checks the same hashes. The content hash is what protects you, and trove protects it from its side: a version's bytes in a local repository never change, and a deleted version number never takes other bytes. A remote repository stores the bytes its upstream sends over TLS; NuGet v3 announces no digest to compare them with, so the lock file's hash is the check against a changed upstream.{{if ne .Class "local"}} A lock file does not keep a withdrawn package alive, though: once the upstream removes an ID, a restore that names it fails with `404`.{{end}}

A package that was restored once sits in the global packages folder of the machine and in the HTTP cache of NuGet; neither asks trove again until you clear them (`dotnet nuget locals all --clear`).
