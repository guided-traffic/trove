{{if eq .Client "npm"}}`package-lock.json` records the address (`resolved`) and the integrity of every tarball. Through trove the addresses lie under the repository the install went through, and `npm ci` fetches the tarballs from them directly, without asking for package documents. A lockfile written through one repository therefore keeps fetching through it after you change `registry=`. To move it to another repository that serves the same versions, replace the old address by the new one in the lockfile; the integrity values stay valid.
{{else if eq .Client "pnpm"}}`pnpm install --frozen-lockfile` installs exactly the versions `pnpm-lock.yaml` records and checks every tarball against the integrity recorded there.
{{else if eq .Client "yarn"}}Yarn Berry writes `yarn.lock` without registry addresses, because trove's tarball addresses have the conventional shape of the registry that serves them. Point `npmRegistryServer` at another repository that serves the same versions and `yarn install --immutable` succeeds without a change to the lockfile.
{{else}}Yarn Classic records the address (`resolved`) and the integrity of every tarball in `yarn.lock`, as npm does in its lockfile; `yarn install --frozen-lockfile` installs exactly what it names, from those addresses.
{{end}}
The integrity values of a lockfile stay valid: a version's bytes in a local repository never change, and a remote repository stores a tarball only once it matches the integrity its upstream announces.{{if ne .Class "local"}} A lockfile does not keep a withdrawn version alive, though: once the upstream removes a version, an install from a lockfile that names it fails with `404`.{{end}}
