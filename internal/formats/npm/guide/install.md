{{if eq .Class "local"}}A local repository serves only the packages published to it; the dependencies of your project that come from elsewhere need a remote or a virtual repository.{{else if eq .Class "remote"}}The first install of a package fetches it from the upstream and caches it; later installs, on any replica, are served from the cache.{{else}}Internal and public packages come through this one address, merged as the first section of this guide describes.{{end}}

Clients check every tarball against the integrity in the package document or the lockfile and stop with `EINTEGRITY` on a difference. A version's bytes in a local repository never change, and a remote repository stores a tarball only once it matches the integrity its upstream announces; an `EINTEGRITY` therefore usually means that the lockfile was written against another registry that served other bytes for the version.
