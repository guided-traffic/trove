The answer lists the advisories of the public advisory database that affect a version your project installs. A name trove treats as internal (a namespace claim of a local repository covers it) is withheld, so the public advisories of a package that happens to share its name are not applied to it. npm prints how many names were withheld (`trove audited <n> of <m> packages from its own advisory data; <k> internal names were not matched against public advisories`); pnpm and Yarn Berry do not show that notice, so their report can be partial without saying so. Until trove has imported the npm advisory data the audit answers `503` `vulnerability_data_unavailable`; `npm install` logs that and completes.

{{if eq .Class "local"}}A local repository answers only in mode `local`; in mode `disabled`, or while vulnerability scanning is switched off, {{else}}In mode `forward` the audit is forwarded to an advisory provider instead: {{if eq .Class "remote"}}by default the remote repository's upstream{{else}}through the first remote member that forwards audits, with that member's provider; you need the read permission on that member{{end}}. trove then sends only the names the forwarding remote repository has fetched from its upstream already, and of those none that is internal: no name that exists in a local repository, falls under a namespace claim or a pin rule, or that the repository's patterns refuse. A name trove has never fetched, such as an internal name nobody claimed or a git dependency, is withheld as well, so the provider learns no name it has not seen from this installation before. A withheld name has no advisories in the answer. npm prints how many names were withheld (`trove audited <n> of <m> packages; <k> internal or not yet proxied names were not sent to the advisory provider`); pnpm and Yarn Berry do not show that notice, so their report can be partial without saying so.
